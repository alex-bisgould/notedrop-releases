1.3.0Categories that know what they areShipped

Everything planned, plus one thing the work itself turned up.

Found while building it: 28 notes sat in seven folders that the registry had no entry for — 14 of them in projects/budget-tracking. buildVariables lists the registry, so a folder missing from it is not a destination the classifier can choose, however full it is. The next budget note could only be filed somewhere else. Adoption is now the first thing the Categories screen offers, above the cosmetic findings, because it is the only one actively costing you something.

Measured while building it: the first competing-category pass reported seven pairs, six of which were track — euchre-tracker against todo-tracker against TaskTracker.app. Words that name the form of a thing rather than its subject no longer count as a collision on their own, which leaves the one real pair: money/budgeting against projects/budget-tracking.

1.4.0Settings you can navigateShipped

Settings showed credentials and three model slots. Everything else had nowhere to live: the store location was a sidebar footer button, re-running setup was a menu item, update behaviour was hardcoded, and seven display preferences sat in localStorage with no UI at all. A preference you cannot find is a preference you do not have.

It also closes the hole 1.3.0 could only detect. Re-running first-time setup regenerated categories.json wholesale, which is how 28 notes ended up in folders the classifier could no longer be offered; and nothing registered a folder the first time a note was filed into it. Both are fixed at the source rather than found by a later scan.

1.5.0Categories you can tell apartShipped

A category's folder name is not its name. projects/budget-tracking is where it lives; "WholeBudget" is what it is.

The border work came out better than planned. Asked to separate money/budgeting from projects/budget-tracking, the model wrote each description to name the other, and stripped the bare terms — budget, expense, receipt — from both aliases, since those were exactly what the two folders had been competing over. It also reported honestly that money/budgeting was empty, so its half of the border was inferred from the name rather than from evidence.

Ideas

Not scheduled. Kept because good ideas are lost by not writing them down, which is the problem this whole app exists to solve.

Making classification better

Classification feedback loop. Moving a note out of where the AI filed it is a correction. Record it, feed recent corrections into the prompt, and the classifier learns this store's particular habits
Bulk re-classify the notes affected when a category's description changes, so improving a description improves the past too
Near-duplicate detection at capture. Today only an exact content hash is caught; pasting a revised version of an existing note should offer to merge
Per-category prompt overrides for categories that need different extraction rules
Confidence calibration report — how often the classifier's confidence matched the outcome, so the gate can be set from evidence rather than taste

Surfacing what is already in the store

Open-tasks view. Every unfinished task across every note, in one list. The tasks exist; there is no aggregate view
Stale-note flag. Open tasks, untouched for N days. This is exactly the failure that started the project — a TODO that went stale in both directions
Weekly digest — filed, still held, tasks still open
Agent activity feed — what other Claude sessions did across the store, from the worklogs they already write
Backlinks, from the related field the classifier already sets
Cost tracking per run; the pipeline already returns token usage and nothing displays it

Capture and reach

iOS capture through the share sheet into a watched iCloud folder
Local model support via Ollama, for notes that should never leave the machine at all
Note templates for recurring shapes — meeting notes, bug reports
Browser capture — select text on a page, send to NoteDrop with the URL
Encrypted vault export, for moving quarantined notes between machines

Housekeeping

Trash preview before emptying. A lesson learned the hard way: a trash folder was emptied without checking, and two discarded notes went with it
Store health check — orphaned .raw.txt files, notes whose folder disagrees with their category field, ids that appear twice
Description staleness — a category whose notes have moved on from what its description says, detected by re-running the drafter and diffing
Auto-close notes whose tasks are all ticked, after confirmation
